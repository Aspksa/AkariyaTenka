# Встроенный перенос Akariya — контролируемый launcher

Кнопка **«Выполнить через Akariya»** в панели **«Перенос Akariya»** запускает управление через supervisor только после двух явных подтверждений: текст `ПЕРЕНЕСТИ` и системное подтверждение браузера.

## Последовательность

1. Веб-интерфейс запрашивает действие через `POST /api/portable/action` с JSON и специальным заголовком. Сервер принимает запрос **только по локальному HTTP-подключению из собственного origin и под управлением launcher**; другие источники отклоняются.
2. Сервер проверяет абсолютный путь и создаёт новый запрос `.portable-state/pending-transfer.json` с маркером текущей supervisor-сессии. Повторная постановка не затирает прежний запрос.
3. Сервер возвращает `202`, инициирует штатное завершение (закрытие HTTP, остановка модулей, сохранение persistence). Код выхода `76` означает, что штатное завершение закончено; если шаг завершения или timeout провалился, перенос выполнять нельзя.
4. Launcher дожидается выхода сервера, останавливает остальные дочерние процессы и освобождает lock жизненного цикла.
5. Только после этого launcher однократно выполняет действие (сравнение, новая копия, направленная синхронизация или восстановление). Применяются прежние проверки состояния, конфликты, SHA-256 и резервные копии. Протокол **не** обходит блокировки другого экземпляра Akariya.
6. Результат записывается в `.portable-state/last-transfer.json`, затем launcher запускает Akariya снова. Панель показывает результат после перезапуска.

## Ограничения

- Для переноса существующих данных обе копии должны иметь одинаковый UUID установки и **общий неизменяемый базовый снимок**.
- Положительный результат создания резервной копии не даёт crash-atomic гарантии при внезапном исчезновении SSD. SQLite нельзя автоматически объединить при независимых изменениях. Транзакционный журнал с восстановлением после обрыва питания и безопасное продвижение общего baseline ещё не реализованы; важные базы сначала проверяйте на тестовых копиях.
- Действия с существующими копиями должны выполняться только после остановки **второго экземпляра** Akariya. Запущенный на втором компьютере экземпляр определяется по блокировке; работа сторонних программ вне протокола не гарантированно определяется.
- Новый перенос не инициируется автоматически после перезапуска launcher: старый request связывается с токеном конкретного экземпляра launcher и не обрабатывается при обычном старте.
- API доступен только на `127.0.0.1` в обычном режиме; интерфейс dev-сервера Vite с другим origin не может отправлять привилегированные запросы.
- Настоящий издательский ключ цифровой подписи не создан и не задействован. Установка обновлений остаётся отключённой до независимой привязки доверенного ключа.
