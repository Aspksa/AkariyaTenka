# Ключ издателя внутри Akariya Tenka

Ключи создаются **самим владельцем** на его доверенном компьютере. Никогда не генерируйте, не восстанавливайте и не публикуйте настоящий приватный ключ в CI, PR или чате.

Импорт ранее созданной пары Ed25519:

1. Обновите локальную копию Akariya до версии, содержащей `scripts/import-publisher-key.mjs`.
2. Откройте командную строку в корневой папке проекта с `AKARIYA.bat`.
3. Запустите `.runtime\node\node.exe scripts\import-publisher-key.mjs "C:\AkariyaPublisherKeys"` (если Node.js находится в другом месте, используйте его полный путь).
4. В терминале введите отдельный пароль минимум из 16 символов дважды. Его ввод скрыт; он не сохраняется в проекте.
5. Скрипт проверит отпечаток SPKI и пару Ed25519, запишет зашифрованный контейнер `keys/private/signing-vault.enc` и публичные файлы `keys/public/publisher-public.pem`, `keys/public/publisher-spki-sha256.txt`. Существующие файлы ключей не перезаписываются.
6. Сохраните независимую защищённую резервную копию ключа и проверенный пароль; не удаляйте временный исходный незашифрованный файл до отдельной проверки резервной копии.

`keys/private/` полностью исключён из Git; файл контейнера с закрытым ключом также не должен коммититься или отправляться через CI. Если Akariya переносится на SSD, шифрованный контейнер можно переносить только контролируемым владельцем отдельно. Пароль должен храниться отдельно от SSD.

**Важно:** импорт не активирует доверие к новому публичному ключу и не включает установку обновлений. Доверенный ключ нужно закрепить и проверить независимым способом; нельзя автоматически доверять любому ключу, найденному в `keys/public/`.

Конфиденциальный исходный каталог за пределами репозитория не перемещается и не очищается автоматически.
